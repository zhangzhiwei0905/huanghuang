# 小程序牌局音效

## Goal

让玩家在微信小程序牌桌上通过语音及时听到出牌与关键操作，增强牌局反馈，同时保持恢复、重连和系统静音行为可控。

## Background

- 用户已在仓库根目录 `huanghuang-audio/mp3-version/` 提供 32 个 MP3 文件。
- 文件包括万、条、筒各 1–9 的 27 种牌名，以及碰、杠、放赖、补杠、胡牌 5 个操作音效。
- 当前 Web 已通过投影差异识别碰、杠和放赖动画；小程序已通过弃牌堆差异识别最近出牌。
- 服务端投影仍是权威状态，客户端音效只能响应新投影，不得改变或推断牌局规则。

## Requirements

- R1：任意玩家新打出一张牌时，小程序播放该牌面的对应语音。
- R2：任意玩家发生碰、普通杠、放赖、补杠或胡牌时，小程序播放对应操作语音；明杠、暗杠和亮牌碰杠共用“杠”音效。
- R3：音效只响应当前连接期间新产生的投影变化。首次打开牌桌、恢复房间、切换房间和断线重连后的首个快照不得补播历史出牌或操作。
- R4：同一投影或连续投影出现多个可识别事件时立即独立播放，允许短语音重叠，不得因等待前一个音效而延迟；每个文件按实测人声窗口跳过前后静音。
- R5：以用户提供的 `mp3-version` 文件作为游戏源文件，通过小程序构建系统打包。
- R6：小程序使用 `InnerAudioContext` 的短音频实现并遵循系统静音开关；页面离开时销毁音频上下文，音频播放失败不得影响游戏。
- R7：不新增服务端字段、数据库状态或客户端规则计算；事件均由连续 `RoomProjection` 的公开字段差异得出。
- R8：牌桌提供音效开关，默认开启，并在微信本地存储中记住用户选择；关闭时立即停止当前音效，重新开启后只播放新事件。

## Acceptance Criteria

- [x] 27 种牌面均能映射到唯一音频文件，缺失或重复文件可由测试/构建发现。
- [x] 小程序在四家任一玩家的新弃牌上播放对应牌名。
- [x] `PONG` 播放碰；`EXPOSED_KONG`、`CONCEALED_KONG`、`INDICATOR_PONG_KONG` 播放杠；`ADDED_KONG` 播放补杠；新增放赖播放放赖。
- [x] 新的胜局结算播放胡牌，流局不播放胡牌。
- [x] 初始活动牌局快照、结算页恢复、版本跳跃和断线重连后的首个快照均保持静音。
- [x] 小程序离开牌桌后不保留活动音频上下文，并遵循系统静音开关。
- [x] 快速连续出牌时每条音效立即独立播放，不等待上一条结束；32 个文件均跳过实测开头静音。
- [x] 等待房和牌局内均可关闭或开启音效，设置跨页面重进保留，关闭后不播放或补播事件。
- [x] `pnpm lint`、`pnpm typecheck`、`pnpm test` 和小程序生产构建通过。
- [ ] 开发者工具或真机实战确认音效可以听见、音量合适且没有明显截断。

## Out of Scope

- 背景音乐、音量滑块和语音包切换。
- 摸牌、洗牌、倒计时、按钮点击或麻将碰撞拟声音效。
- 服务端广播专用音效事件。
- 对用户录音做裁剪、降噪、响度归一化或重新配音。
- Web 端音效。
