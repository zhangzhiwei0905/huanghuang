# 网页麻将三门牌面 SVG 素材

## Goal

为网页麻将游戏提供一套风格统一、可直接作为前端静态资源使用的 27 张牌面 SVG，覆盖万、条、筒三门花色的 1～9 点。素材在 28px～68px 显示尺寸下仍应清晰可辨，并将牌体、背景、圆角和阴影的控制权完整留给前端 CSS。

## Background

- 目标目录 `apps/web/src/assets/tiles/` 当前不存在，需要随素材一起创建。
- 本任务将素材接入统一的 `MahjongTile` 组件，但不修改现有玩法逻辑或服务端协议。
- 用户否决了第一版手绘路径，最终素材必须改用 [`lietxia/mahjong_graphic`](https://github.com/lietxia/mahjong_graphic) 仓库中透明背景的 `1m.svg`～`9m.svg`、`1s.svg`～`9s.svg`、`1p.svg`～`9p.svg`。
- 上游仓库采用允许使用、复制、修改、分发及商用的 M+ 字体许可条款；本次锁定来源提交 `3e275804ff58325306710bef3a7406860444bc6a`。
- 每张牌都是独立、自包含的 SVG 文件，不依赖系统字体、外部图片或外部样式。

## Requirements

### R1 — 文件范围与命名

- 在 `apps/web/src/assets/tiles/` 下生成且仅生成本套素材需要的 27 个文件：
  - `wan-1.svg` ～ `wan-9.svg`
  - `tiao-1.svg` ～ `tiao-9.svg`
  - `tong-1.svg` ～ `tong-9.svg`
- 不包含风牌、字牌或牌背。

### R2 — SVG 技术约束

- 根元素统一使用 `viewBox="0 0 240 320"`。
- 背景透明；不得绘制牌体底色、牌体外框、圆角、投影或高光。
- 可见图形保持在约 16px 安全边距以内。
- 只使用自包含的 SVG 矢量图元与纯色，包括 `path`、`circle`、`rect`、`g`、`defs`、`symbol`、`use` 等。
- 不使用 `text`、`image`、位图、滤镜、模糊、渐变、脚本或外部资源。

### R3 — 万字牌

- 分别取自上游 `1m.svg`～`9m.svg`，保持其万子字形路径，不再自行绘制或描摹。
- 所有字形仍必须是内嵌矢量路径，不能依赖系统字体文本。
- 将上游暗红映射为 `#9b4038`，黑色数字映射为辅助蓝 `#405d70`。

### R4 — 条子牌

- 分别取自上游 `1s.svg`～`9s.svg`，保持原始雀鸟、竹条细节与排布，不再自行绘制或重排。
- 将上游绿色及黑色映射为墨绿 `#2d6653`，上游暗红映射为金色 `#967335`。

### R5 — 筒子牌

- 分别取自上游 `1p.svg`～`9p.svg`，保持原始筒饼细节与排布，不再自行绘制或重排。
- 将上游深蓝映射为蓝 `#405d70`，上游暗红映射为金色 `#967335`。

### R6 — 视觉一致性

- 27 张牌完整沿用同一上游素材集的几何语言、线宽观感与细节层级。
- 适配过程只允许改画布、统一缩放／位移、颜色和文件名，不修改上游路径数据。
- 在 28px～68px 等比缩小时，花色与点数仍应快速辨认。

### R7 — 来源记录

- 在任务研究记录中保存仓库 URL、锁定提交、原始文件映射和许可链接。
- 生产 SVG 保持自包含，不带运行时外部引用。

### R8 — 前端统一接入

- `MahjongTile` 的万／条／筒牌面全部改为对应 SVG 资源，不再用文字、圆点或竹条 CSS 图元拼接。
- 手牌、摸牌、弃牌、公开组合、动作提示、亮牌和已放赖区域继续复用同一个 `MahjongTile` 组件，因此自动获得同一套牌面资源。
- 牌桌中央“赖子”区域必须与“亮牌”区域一致，使用紧凑型 `MahjongTile` 展示 `wildcardKind`，不得再用 `tileKindLabel()` 文本模拟牌面。
- 赖子、亮牌、选择、高亮和动作动画等外层状态样式继续由 CSS 控制，不改动 SVG 内部路径。
- 保持现有可访问名称：视觉图片使用空 `alt`，牌组件继续通过 `aria-label` 描述点数、花色和赖子状态。

- 风牌、三元牌、花牌、牌背及牌体容器样式。
- 动画、交互状态、3D 效果或多套配色主题。
