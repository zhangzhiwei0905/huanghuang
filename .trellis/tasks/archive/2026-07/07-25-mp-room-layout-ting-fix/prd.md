# 优化小程序牌桌布局并修复听牌提示

## Goal

在微信小程序横屏牌桌中重新整理四个座位的信息与公开碰杠区域，确保昵称、积分等信息始终处于卡片边界内，任意两个座位的公开牌组互不遮挡；同时恢复已实现但尚未在线上生效的“打出后听牌”新手辅助。

## Confirmed facts

- 上、下座位的玩家元信息当前使用单行 `white-space: nowrap`，但没有裁切或省略约束，窄屏时会越出卡片。
- 玩家身份信息和公开碰杠牌组当前共用同一个绝对定位容器；左侧玩家与本玩家的牌组较多时会进入同一空间并重叠。
- 听牌辅助代码已经在提交 `a6f31d0` 中完成，协议投影版本为 5；当前体验版前端可渲染 `tingHints`。
- 线上容器仍运行 `huanghuang-app:login-resume-20260724`，revision 为 `login-resume-20260724`，镜像内没有 `tingHints`，因此线上后端不会下发听牌数据。
- 小程序构建此前在未传 `TARO_APP_API_BASE` 时默认写入 `http://127.0.0.1:3000`，会让开发者工具和体验版持续触发合法域名错误。

## Requirements

### R1 玩家信息不溢出

- 四个座位的昵称、积分、手牌数、倍率和离线状态必须限制在自己的信息卡片内。
- 昵称过长时允许省略，但积分、手牌数和倍率等关键状态必须保持可读。
- 上、下座位在常见横屏手机宽度与窄屏高度下均不得越出边框或安全区。

### R2 公开碰杠区重新布局

- 身份卡与公开碰杠牌组拆分为独立的视觉区域，不再由牌组内容撑大身份卡。
- 四个座位各自拥有固定的展示轨道；左侧玩家与本玩家同时拥有大量碰、杠时不得相互覆盖，也不得遮住手牌、操作按钮、牌河或听牌候选卡。
- 每组碰、杠仍须保留明确的组间边界、牌面和类型标签，玩家能够一眼分辨各组公开信息。
- 不改变牌局逻辑、座位映射、动作提示和已有动效语义。

### R3 听牌辅助恢复生效

- 当前玩家处于合法出牌阶段时，所有“打出后可听牌”的物理手牌上方显示小“听”标识。
- 第一次点击带“听”标识的牌后，该牌进入选中态，并在牌上方展示打出它之后可胡的全部牌种、合并后的真实倍率与按公开信息推导的真实剩余张数。
- 选择不同弃牌时，候选卡及时切换；选择非听牌、回合结束或合法动作变化时，旧候选必须消失。
- 赖子规则沿用现有权威投影：打出后手里没有赖子时，赖子可作为听牌候选；打出后手里已有赖子时，不显示赖子候选。
- 小程序不得在客户端重新计算胡型、倍率或剩余数量。

### R4 上线一致性

- 生产小程序继续使用 `https://huanghuang.amazingzz.xyz`。
- 普通 `build:weapp` 默认编译生产域名；只有本地联调时才显式覆盖为 `http://127.0.0.1:3000`。
- 后端部署必须包含提交 `a6f31d0` 之后的协议、引擎和服务端实现，并保留现有微信登录配置与持久化数据。
- 上线后通过真实房间投影确认 `schemaVersion: 5` 且合法出牌者能收到非空 `tingHints` 场景。

## Acceptance Criteria

- [x] iPhone 12/13 (Pro) 横屏尺寸下，上、下玩家信息没有文字越界。
- [x] 左侧玩家和本玩家分别达到四组公开碰/杠的极端场景时，各组仍互不遮挡，且不挡住核心对局区。
- [x] 普通昵称、超长昵称、离线标识、不同倍率组合均保持关键状态可读。
- [x] 可听牌弃牌显示“听”；首次点击后的候选牌、倍率和公开剩余数量继续由现有投影与组件链路渲染。
- [x] 切换不同可听弃牌时候选内容正确切换；非听牌和非出牌阶段不显示候选。
- [x] 赖子候选的有/无符合“打出后手中是否已有赖子”的规则。
- [x] 布局、听牌组件、投影与服务端相关自动化测试通过。
- [x] 生产容器 revision 更新，线上真实房间投影包含 schemaVersion 5 和非空 `tingHints`。

## Resolved decision

- 极端四组碰/杠采用全部一次性紧凑展示，不增加局部滑动；碰杠属于对局中的公开关键信息，需要一眼看全。
