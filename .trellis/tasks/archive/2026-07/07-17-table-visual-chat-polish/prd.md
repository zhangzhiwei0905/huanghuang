# 牌桌信息与聊天视觉优化

## Goal

在不修改麻将规则、现有指令语义和房间流程的前提下，优化横屏牌桌的信息层级、玩家信息、聊天与本局结算，让关键状态更直观并减少无意义边框。

## Background

- 当前麻将牌已使用 27 张 SVG 矢量图，但亮牌仍有独立虚线轮廓，动作提示和放赖展示也存在额外容器边框。
- 对手手牌数量当前由一排背面长方形模拟，不便于快速读取。
- `RoomProjection.wallRemaining` 已提供权威牌墙余量，但主要显示在顶部信息栏而不是牌桌中央。
- 聊天消息已经包含 `senderSeat`，可以将消息气泡定位到发送者头像附近。
- 当前结算投影包含倍率与积分变化，但没有向客户端公开所有玩家的终局手牌。

## Requirements

### R1. 麻将牌与特殊牌边框

- 移除麻将牌周边不承载状态含义的透明/装饰框，保留牌体本身、选中态、赖子标记和合法操作高亮的可辨识性。
- 牌桌中央的亮牌与赖子使用一致的牌面展示，亮牌不再使用虚线轮廓。
- 碰、杠、补杠和放赖的瞬时提示只展示 SVG 麻将牌，不使用独立卡片边框。

### R2. 玩家信息与头像位

- 每位玩家信息区预留一个固定正方形头像位，当前为空白，不使用默认人物图标。
- 移除用多个长方形模拟对手手牌的展示。
- 直接显示每位玩家当前剩余手牌张数，同时保留昵称、连接/托管状态、积分和个人倍率。

### R3. 牌墙余量

- 在牌桌中央的回合状态区域展示服务端提供的 `wallRemaining`。
- 顶部不重复展示同一余牌信息。

### R4. 终局结算

- 自摸或流局后的结算弹窗按玩家展示终局暗手牌，牌面必须复用 SVG 麻将牌组件。
- 每行同时展示玩家昵称、个人倍率、本局积分变化和累计积分。
- 硬胡、软胡及赢家信息保持清晰；好友房和人机房的继续/返回流程保持不变。
- 服务端仅在终局结算投影中公开四家终局手牌，牌局进行中仍只公开自己的手牌。

### R5. 聊天输入与气泡

- 好友房横屏牌局在屏幕下方中央展示聊天输入框和发送按钮。
- 输入框获得焦点后允许系统键盘正常弹出，布局继续使用现有动态视口和安全区变量。
- 消息发送成功后，以气泡展示在发送者头像附近，不遮挡麻将牌或中央弃牌区。
- 每条消息显示约 3 秒后渐隐并从客户端临时列表移除。
- 聊天消息长度、Socket 事件与服务端校验协议保持不变。

### R6. 放赖持久展示

- 放赖区域去掉独立边框和背景，视觉结构与公开碰杠牌组保持一致。
- 同一玩家多次放赖时显示一张赖子牌及 `×N` 数量，个人倍率继续在玩家信息区单独展示，避免将次数与倍率混淆。

### R7. 响应式与主题一致性

- 低调与精美主题使用同一组件树和相同信息结构。
- 桌面、平板和手机横屏均保持头像、聊天气泡、聊天输入、结算手牌和操作按钮不重叠。
- 动画继续尊重 `prefers-reduced-motion`。

### R8. 兼容性与范围

- 不修改胡牌、碰杠、放赖、计分或倒计时规则。
- 不改变现有游戏命令与聊天事件格式。
- 不引入新的前端组件或动画依赖。

## Acceptance Criteria

- [x] AC1: 所有普通牌面没有额外透明外框；亮牌无虚线；动作提示与放赖持久展示无容器边框。
- [x] AC2: 四家玩家区均有空白正方形头像位和明确的剩余手牌张数，不再渲染模拟牌背长方形。
- [x] AC3: 牌桌中央显示权威余牌数，顶部不再重复显示。
- [x] AC4: 终局结算的四个玩家行均使用 SVG 牌面展示终局手牌，并显示个人倍率、本局正负积分和累计积分。
- [x] AC5: 牌局进行中，非当前用户的 `PlayerProjection.hand` 仍为 `null`；只有 `roundSettlement` 含四家终局手牌。
- [x] AC6: 好友房聊天输入位于屏幕下方中央；消息出现在对应发送者头像附近并在约 3 秒后消失。
- [x] AC7: 多次放赖以一张赖子牌加 `×N` 表示次数，不再使用独立边框。
- [x] AC8: 相关单元测试、lint、TypeScript 检查和生产构建全部通过。
- [x] AC9: 844×390 手机横屏与桌面横屏人工检查无关键内容重叠，低调/精美主题均可读。

## Out of Scope

- 头像上传、头像 URL、图片存储和账号系统。
- 聊天历史、离线消息、表情和快捷语。
- 结算回放或历史战绩入口。
- 麻将规则、计分公式和网络协议重构。
