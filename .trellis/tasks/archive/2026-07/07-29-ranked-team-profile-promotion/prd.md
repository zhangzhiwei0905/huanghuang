# 实现单人组队排位与段位体验

## Goal

在现有四人麻将和竞技段位体系上，补齐可发现、可组队、可持续反馈的排位体验：

- 玩家在主页、等待房和对局内点击任意已占用头像，都能查看统一的玩家详情。
- 首页将排位入口拆分为单人排位与组队排位。
- 组队排位拥有独立等待牌桌，队员准备后由房主发起匹配，并可取消后重新准备。
- 所有竞技段位使用同一套高品质徽章与明确段位文字。
- 发生实际段位晋升时，在结算阶段播放一次具有仪式感的晋升动画。

## Requirements

### 玩家详情

- 主页登录头像可点击，打开与牌桌内一致的玩家详情弹窗。
- 等待房与对局内所有已占用座位的头像均保持可点击。
- 详情至少展示：名称、头像、当前牌桌积分、竞技段位、永久成就。
- 不在牌桌中时，牌桌积分展示为 `0`，不额外引入新的积分或经济系统。
- 未绑定竞技资料的机器人或普通好友房玩家仍可查看基础信息，竞技区明确显示无永久竞技战绩。

### 排位入口

- 首页原“排位赛”入口调整为“单人排位”和“组队排位”两个清晰入口。
- 单人排位保持现有匹配、取消、断线恢复、返回对局、体验期机器人补位逻辑。
- 组队排位创建固定竞技规则的等待牌桌，并生成可分享/复制的房间号。
- 组队等待牌桌不允许添加机器人、修改底分、修改难度或自动开局。
- 队员可以切换准备/取消准备。
- 只有房主可以点击“开始匹配”，且必须满足组队人数下限与所有当前队员已准备。
- 匹配中任何真人队员均可点击“取消匹配”。
- 取消匹配后保留组队房间和座位，但清空所有人的准备状态；继续匹配前必须重新准备。
- 玩家离开正在匹配的队伍时，先取消整队匹配并清空其他成员准备状态，避免队伍状态与匹配队列分裂。
- 匹配成功后四名玩家进入现有竞技对局与结算流程，组队关系不改变胜负和段位计算。

### 段位徽章

- 使用当前已确认的 V3 视觉方向，为黑铁、青铜、白银、黄金、铂金、钻石、星耀、雀神提供 8 个源代码内置徽章资产。
- 段位组件根据 `rankDisplay.majorIndex` 选择徽章，不依赖展示文案解析。
- 徽章下方始终展示完整段位文字，例如 `星耀Ⅲ`、`雀神5级`。
- 主页账号区、玩家详情、排位匹配状态、结算段位变化与晋升动画复用同一段位组件或同一资产映射。

### 晋升动画

- 仅当竞技结算的 `afterRankLevel > beforeRankLevel` 且展示段位发生变化时播放晋升动画。
- 动画展示旧段位、方向变化、新段位，并突出文案，例如 `段位晋升`、`星耀Ⅱ → 星耀Ⅰ`。
- 动画完成后仍可查看现有完整结算和保护卡信息，不遮断结算操作。
- 动画需要支持 `prefers-reduced-motion`，在减少动态效果时使用简化淡入。
- 同一结算快照只播放一次，页面投影刷新不得重复触发。

### 已确认的产品规则

- 组队排位允许 2–4 人发起匹配，队伍不可拆分，由系统用单排玩家或其他队伍补齐空位。

## Acceptance Criteria

- [x] 主页点击自己的头像会打开详情，显示名称、头像、牌桌积分 0、段位和成就。
- [x] 好友等待房、组队等待房、单排竞技对局与普通对局内，点击任意已占用头像均打开统一详情。
- [x] 首页同时存在“单人排位”和“组队排位”，单人排位现有行为无回归。
- [x] 组队房中全员准备后仅房主能发起匹配；条件不足时按钮禁用并给出原因。
- [x] 匹配中任一队员可取消；取消后所有真人均变为未准备，且房间保持可继续使用。
- [x] 离队、断线恢复、房主解散和匹配成功均由服务端权威状态驱动，重启后不产生幽灵队列。
- [x] 所有段位展示使用正确的大段位徽章，徽章下显示完整小段位/雀神等级文字。
- [x] 从 `星耀Ⅱ` 晋升到 `星耀Ⅰ` 等实际升级会播放一次晋升动画；不变或降级不播放。
- [x] 协议、服务端、匹配算法与小程序关键纯逻辑均有自动化测试。
- [x] `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过。

## Notes

- 本任务不修改 Figma 文件；段位视觉以已确认的最新徽章稿为实现依据。
- 现有竞技段位只有等级制，没有独立“竞技积分”账本，因此详情中的积分沿用权威牌桌累计分。
- 组队补位规则已确认并写入 `design.md` 与 `implement.md`。
