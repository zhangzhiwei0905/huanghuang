# 重设计小程序候场与牌桌

## Goal

把好友房候场与对局牌桌改造成一个横屏、无页面滚动、信息完整的小程序游戏界面。玩家进入房间后能直观看到四个方位的头像、昵称、积分、联网和准备状态，并在自己的方位直接准备或取消准备；全员准备后以明确的开局提示平滑进入牌局。

## Background

- 当前房间页位于 `apps/miniprogram/src/pages/room/index.tsx`，候场和对局共用同一个页面。
- 根容器使用 `height: 100vh`；候场卡片使用 `max-height: 100%` 和 `overflow: auto`，这是用户看到页面不完整及滚动条的直接来源。
- 当前候场区由顶部工具栏、居中大卡片、十字座位、底分按钮和底部操作组成，层级较多，视觉上不像一个整体牌桌。
- `RoomProjection.lobbySeats` 已提供每个座位的头像、昵称、积分、房主、自身、联网和准备信息，不需要新增后端资料字段。
- 当前玩家已经可以通过 `roomCtrl.ready()` 准备或取消准备；服务端在好友房四个座位全部有人且全部准备后立即调用 `startRound()`。
- 服务端从 `WAITING` 切到 `PLAYING` 时不会先等待客户端弹框，因此开局提示必须是客户端的阶段过渡层，不能阻塞服务器游戏状态。
- 本项目只支持手机横屏，并已有安全区、低版本 WXSS 和微信开发者工具自动化约束。

## Requirements

### R1 单屏全屏布局

- 候场和对局都必须占满当前小程序可用视口，页面本身不得出现纵向或横向滚动条。
- 使用微信小程序 WebView 已验证可用的 `100vh`，配合页面 `disableScroll`、根级 `overflow: hidden` 和安全区；不能依赖在微信页面节点中无法可靠传递的纯百分比高度链。
- 所有关键操作在常见小屏横屏设备中一次完整展示，不通过滚动才能触达。
- 内容较多时优先压缩间距、字号和非关键装饰，不允许让整体页面滚动。

### R2 小程序牌桌式候场

- 候场页面直接呈现一个完整牌桌，不再使用“背景上再放一个可滚动大卡片”的网页面板结构。
- 四个座位按相对玩家方位展示：自己固定在下方，对家在上方，其他玩家在左右。
- 每个座位展示头像、昵称、积分、房主/自己标识、在线状态和准备状态；空位展示清晰的邀请状态。
- 房号、底分、连接状态、复制/分享和离开/解散保持可用，但收敛成小程序游戏顶部工具区，不能挤压主牌桌。
- 视觉使用现有墨绿、米白和麻将桌素材，减少通用网页卡片感，保持与首页和实战牌桌一致。

### R3 自己方位的准备交互

- “准备/取消准备”按钮固定放在自己的下方座位区域，避免与其他管理操作混在一起。
- 未准备时使用明确主按钮；已准备时显示醒目状态并提供“取消准备”。
- 点击后要有按压和忙碌反馈，服务端返回后四个座位状态同步更新。
- 离开房间、分享邀请、房主修改底分和解散房间继续可用，但不能抢占准备主操作层级。

### R4 全员准备后的开局提示

- 当页面从 `WAITING` 首次转换为 `PLAYING` 时显示小程序风格的全屏过渡提示。
- 提示必须说明“全员已准备”和“游戏开始”，显示 `3、2、1` 三秒倒计时后自动消失，不需要玩家点击确认。
- 提示是非阻塞客户端覆盖层：底层已经是最新牌桌投影，提示结束后自动显露牌局。
- 页面恢复、重连或从后台回到一个已经进行中的牌局时不得重复播放开局提示。

### R5 对局牌桌整理

- 对局页面保持四方位玩家头像、昵称、积分、手牌数、倍率和离线状态。
- 顶部信息、玩家座位、中央信息、弃牌区、自己手牌和动作按钮必须在单屏内互不遮挡。
- 自己手牌允许组件内部的必要横向容错，但页面和主要牌桌不得出现滚动条。
- 不改变麻将规则、服务端行动权或结算逻辑。

### R6 Compatibility and verification

- 继续使用 Taro/React/SCSS，不引入新 UI 框架或远程字体。
- 避免小程序低版本 WebView 不支持的 CSS；遵守现有 `vmin` 像素下限和 `color-mix()` 禁用约束。
- 使用微信开发者工具端口 11352 验证常见横屏尺寸的候场、准备状态、开局过渡和对局页面。
- 运行 lint、typecheck、完整测试和生产小程序构建。

## Acceptance Criteria

- [x] 候场与对局页面都没有页面级横向/纵向滚动条。
- [x] 常见手机横屏视口内可完整看到顶部工具、四个座位和自己方位的主操作。
- [x] 四个座位正确展示头像、昵称、积分、准备/联网状态及房主/自己标识。
- [x] 玩家可在自己方位准备和取消准备，按钮及座位状态与服务端投影一致。
- [x] 房主仍可切换底分、分享、复制房号和解散；其他玩家不能看到房主专属控制。
- [x] 第四位玩家准备触发 `WAITING → PLAYING` 后只播放一次“全员已准备 / 游戏开始”过渡。
- [x] 直接恢复或重连到 `PLAYING` 不重复播放开局提示。
- [x] 开局提示结束后牌桌完整可操作，头像、昵称、积分等玩家信息继续显示。
- [x] 360–555 CSS px 高度的主流横屏设备上，玩家卡片、弃牌、中央信息、手牌和动作按钮无关键遮挡。
- [x] 不修改游戏规则和服务端自动开局条件。
- [x] lint、typecheck、完整测试、变更范围格式检查及生产构建通过。

## Out of Scope

- 修改四人全部准备才开局的服务端规则。
- 改为房主手动开始游戏。
- 竖屏布局、平板专属布局或网页端同步改版。
- 修改结算规则、聊天系统或新增表情/语音功能。
- 代替用户上传体验版或正式发布小程序。
