# 接入麻将游戏特效动画

## Goal

将 `/Users/zhang/Documents/Codex/2026-07-27/qin/outputs/mahjong-lottie`
中的麻将反馈动画接入 Taro 微信小程序牌桌，让已经由牌局投影确认的碰、杠、
补杠、放赖和胡牌事件获得与玩家位置一致的一次性视觉反馈；碰采用更克制的
无牌面反馈，其余需要辨认牌面的动作继续展示权威牌面。

## Background

- 目标客户端是 `apps/miniprogram`，牌桌入口为
  `apps/miniprogram/src/pages/room/index.tsx`。
- 动画包包含 `peng`、`gang`、`bu-gang`、`fang-lai`、`hu-pai` 五个
  512×512、60fps、透明背景的纯 Shape Layer Lottie 动画。
- 动画包提供面向微信小程序的本地 CommonJS 数据模块、牌面替换工具和
  `lottie-miniprogram` 示例；五份本地数据合计约 280KB。
- 现有小程序已经通过相邻 `RoomProjection` 差分驱动游戏音效，并遵守首次加载、
  断线重连和版本跳跃时不回放历史事件的约束。

## Requirements

- 仅在服务端牌局投影确认事件后播放动画，不因按钮点击提前播放。
- 根据新增或升级的公开副露分别播放碰、杠或补杠动画；碰只展示动作文字与
  轻量冲击反馈，不展示具体牌面，杠和补杠继续传入真实牌面。
- 根据新增的公开赖子播放放赖动画，并传入真实赖子牌面。
- 服务端确认胜局时播放胡牌动画；流局不播放。
- 胡牌时先完整播放 2.8 秒胡牌动画，再向玩家展示结算面板。
- 对局中的动作特效播放完成后，牌局才推进到后续玩家或后续摸牌步骤；推进和
  发牌不能在特效仍播放时提前呈现。
- 普通动作特效定位到动作玩家头像附近；碰采用更小的方形舞台并轻微贴入头像
  边缘。胡牌使用横屏中央的等比正方形舞台，外层遮罩覆盖牌桌但不拉伸动画。
- 房间内每个客户端都播放所有玩家的已确认动作特效，不限于本机玩家。
- 单次特效按视觉层级采用不同节奏：碰 2.0 秒、杠 2.2 秒、补杠 2.3 秒、
  放赖 2.5 秒、胡牌 2.8 秒。
- 动画为一次性播放且视觉层不截获点击；服务端特效阶段会暂时清空合法牌局动作。
- 同一房间同一时间最多存在一个服务端特效阶段，前一阶段完成前不会接受或产生
  下一个牌局动作。
- 首次进入或断线重连时，仍有效的当前特效从已流逝进度继续播放；已结束的历史
  特效以及版本跳跃期间错过的特效不补播。
- 页面卸载时销毁动画实例和 Canvas 资源。
- 保持微信小程序横屏、安全区、原生 Canvas 与主包体积兼容。
- 由服务端创建并持久化带唯一 ID、动作、玩家、牌面和起止时间的特效阶段；
  阶段期间不接受牌局命令、不给机器人调度新动作，也不提前应用已计算好的后续
  回合状态。
- 特效阶段到期后由服务端原子应用预先确认的牌局状态，再启动后续玩家的行动
  计时；服务重启后仍能从持久化房间快照继续完成该阶段。
- 小程序只消费服务端投影的特效阶段，不自行推断何时允许牌局继续。

## Acceptance Criteria

- [x] 碰、明杠/暗杠/亮杠、补杠、放赖和胡牌成功后各自播放对应动画。
- [x] 碰动画仅展示“碰”动作章与轻量冲击反馈，不展示具体牌面；杠/补杠/放赖
  继续展示实际事件牌面，普通动作均出现在动作玩家附近。
- [x] 同一已确认动作在房间内各客户端均可见，且单次特效约持续 2–3 秒。
- [x] 胡牌动画仅对胜局播放，在牌桌中央保持原始正方形比例；流局不播放。
- [x] 胡牌动画结束前不显示结算面板，结束后显示服务端已确认的结算结果。
- [x] 普通动作特效期间不提前呈现下一回合或后续摸牌；动画结束后再一致地推进。
- [x] 首次加载或重连只续播仍有效特效的剩余部分；已结束事件和非连续版本更新
  不补播。
- [x] 连续事件不会造成多个 Canvas 动画叠加、残留或卸载后继续运行。
- [x] 特效阶段内真人命令和机器人动作都不会推进牌局；阶段到期只应用一次已确认
  状态，并刷新正确的后续行动计时。
- [x] 服务在特效阶段中重启后不会丢失、重复或提前应用已确认动作。
- [x] 小程序 TypeScript 检查和生产构建通过。
- [x] 构建产物包含所需动画数据，主包未超过微信小程序大小限制。
