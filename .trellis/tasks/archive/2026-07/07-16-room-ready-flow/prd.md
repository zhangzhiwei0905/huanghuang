# 房间准备与人机入口流程优化

## Goal

将“好友房”和“人机对战”拆分成两个清晰的产品流程：创建或加入好友房后先进入四人等待房，所有真人准备完成才开始一局；每局结算后返回同一等待房重新准备。人机对战则作为主页独立入口，不再由创建好友房隐式启动。

## Background

- 当前主页只有“创建房间”和“加入房间”两个切换入口，创建按钮文案为“创建并开局”。
- 当前服务端创建房间时立即生成一位真人加三位机器人并启动牌局；后续加入的真人先进入等待区，四名真人准备后才替换机器人并重开真人局。
- 当前真人局结束后，结算弹框停留约 4 秒，服务端随后自动创建下一局，不要求重新准备。
- 当前协议已经包含 `selfReady`、`waitingPlayers` 和每个等待玩家的 `ready` 状态，但“已入座真人”和“等待真人”是两套结构，不能完整表达四个固定座位的等待状态。
- 上一轮已确认：好友房仅通过房间码或邀请进入，无公开匹配；机器人局不计入真人积分；房主可设置本局后解散。

## Requirements

### R1. 主页入口拆分

- 主页将“人机对战”提升为与“创建房间”“加入房间”同级的独立入口。
- “人机对战”是独立单人模式，点击后直接开启一位真人与三位机器人的一局游戏。
- 人机对战不显示房间邀请入口，也不允许其他真人通过房间码或邀请链接加入。
- 人机对战每局结束后不自动续局，必须由唯一真人玩家确认“继续游戏”或“退出到主页”。
- 人机对战选择“继续游戏”时保留本次挑战的累计积分；退出主页后结束该次挑战，下一次进入人机对战重新从 0 分开始。
- “创建房间”只创建好友房和进入等待房，不立即发牌，也不启动机器人行为。
- “加入房间”进入目标好友房的空座位和等待房，不加入任何正在运行的机器人过渡局。

### R2. 好友房等待与准备

- 好友房固定展示四个座位；进入房间的真人立即占用一个空座位。
- 每个玩家能看到自己的座位、其他座位的玩家昵称以及每位真人的“已准备/未准备”状态；空座位明确显示为等待加入。
- 玩家可点击准备；只有四个座位都是真人且四人全部准备后，服务端才开始本局。
- 本局开始时，所有玩家都收到清晰但不打断操作的开局提示。

### R3. 局间重新准备

- 每局自摸或流局完成后先展示本局结算。
- 结算确认或展示结束后，所有仍在房间的玩家回到该好友房等待页面。
- 每局结束后清空全员准备状态；四人必须重新准备，全部完成后才开始下一局。
- 房间码、座位、房主身份、累计积分和底分跨局保留；单局手牌、个人倍率和单局状态按新局规则重置。
- 房主主动解散时立即关闭房间并让全部成员返回主页，不再等待本局结束。

### R4. 兼容既有规则

- 不改变麻将规则、胡牌规则、杠分、自摸结算、断线托管、邀请房底分和房主转让规则。
- 服务器仍是房间阶段、座位、准备状态和开局行为的唯一权威。
- 页面刷新或断线重连后应恢复到当前房间阶段：等待房、对局中或单局结算。

### R5. 当前回合指示

- 好友对战和人机对战的牌桌都必须在当前行动玩家附近显示方向明确的箭头。
- 箭头随服务端权威行动座位更新，并与现有头像边框高亮和桌面中央玩家名称共同表达当前回合。
- 响应阶段应保持对实际响应玩家的指示；本局结束或等待房阶段不显示回合箭头。

### R6. 准备状态切换

- 好友房等待阶段的玩家可在“准备”和“取消准备”之间切换。
- 取消准备后，其他玩家立即看到该玩家恢复为未准备；只有当前四人同时处于已准备状态时才开局。
- 底分发生变化时清空全员准备状态，确保所有玩家按新底分重新确认。

### R7. 解散、离房与房主权限

- 房主在等待或对局阶段主动解散时立即关闭房间，房间内全部客户端退出到主页并显示“房主已解散房间”。
- 主动离房会立即释放该玩家的房间成员身份；再次进入只能走“加入房间”流程。
- 好友房房主离开时，从仍在房间的真人中随机转让房主；无人剩余时关闭房间。
- 只有当前房主可在好友房等待阶段修改底分；新房主自动获得该权限。

### R8. 对战聊天

- 好友对战过程中，房内真人可发送最多 60 个字符的纯文本消息。
- 消息由服务端校验成员身份后实时广播给房内客户端，不写入历史记录或房间快照。
- 消息展示在牌桌之外的底部操作栏，不遮挡麻将、动作按钮或结算内容。
- 每条消息显示后在 5 秒内逐渐变淡并移除；减少动态效果系统设置下可取消渐变但仍按时移除。

### R9. 按需动作按钮

- 牌桌不再常驻展示禁用的碰、杠、补杠和自摸按钮；只渲染服务端 `legalActions` 当前允许的主要动作。
- 出牌、放赖、碰、杠、补杠、自摸统一放在本人手牌上方；底部操作栏只保留“过”“继续打牌”等辅助动作。
- 响应他人弃牌时，主要动作栏只出现当前可用的碰和/或杠，不混入自摸、补杠、出牌等无关按钮。
- “打出”统一改名为“出牌”，作为最高频动作使用稳定、醒目的主按钮；选择可出的手牌后才可点击，双击麻将仍可直接出牌。
- “放赖”使用有辨识度但克制的特殊样式，并明确表达倍率翻倍；仅选择赖子实体后可点击。
- 碰、杠和补杠共享基础动作视觉语言；杠按钮通过副标签区分明杠和暗杠，亮牌特殊碰仍归入碰按钮。
- 自摸使用胜利态视觉和“本局获胜”副标签，仅在服务端允许 `DECLARE_WIN` 时出现。
- 所有按钮保持至少 44px 触控高度、可见键盘焦点和减少动态效果兼容；低调与精美模式共用同一组件结构。

### R10. 成熟化牌桌体验

- 普通手牌第一次点击选中并上移；再次点击同一张牌确认出牌，点击其他牌切换选择。赖子不得通过二次点击绕过“放赖”动作。
- 游戏命令提交使用同步互斥锁并展示提交状态；Socket 确认超时后必须恢复操作，禁止重复请求和无限等待。
- 断线重连必须重新订阅房间、明确展示恢复状态，并直接应用服务端最终投影，不回放过期动画。
- 新摸牌、最新弃牌和手牌重排使用短促的 transform/opacity 动画；动画不修改权威投影，也不阻塞命令确认。
- 当前行动玩家继续由 `actingSeat` 决定；轮到本人时同时强化本人信息、手牌区和倒计时，等待网络时给出明确状态。
- 亮牌、赖子、放赖展示区和个人倍率提供统一反馈；软胡与硬胡在结算弹框中使用文字与视觉双重区分。
- 倒计时更新不得驱动整张牌桌高频重渲染；监听器、定时器和临时动画必须完整清理。

### R11. 房间自动回收与 iOS/PWA

- 好友房每次进入等待阶段后 3 分钟仍未开局，服务端自动关闭房间；初次创建和每局结束后的重新准备都适用。
- 超时关闭后，房间内玩家返回主页并看到“3 分钟未开始，房间已解散，请重新创建或加入房间”。
- 房主主动解散不再等待本局结束；服务端立即关闭房间并通知所有成员。
- 房主主动离房时将房主身份转给房内其他真人；没有其他真人时立即关闭并回收房间。
- 已关闭房间在通知窗口结束后从服务端内存容器和 SQLite 房间表移除；进程启动时也清理遗留关闭行。
- iPhone/iPad Safari 使用动态视口和安全区布局，地址栏伸缩不得遮挡牌桌、手牌和主要动作。
- 提供可安装 PWA：独立窗口启动、横屏方向、主题色、Apple Web App 元数据、离线应用壳；游戏状态和命令仍必须联网并以服务端为准。

## Acceptance Criteria

- [x] AC1：主页同时提供“创建房间”“加入房间”“人机对战”三个同级入口。
- [x] AC1a：人机入口直接开启一真人三机器人对局，牌桌不提供邀请能力，结算后只有玩家确认继续才开启下一局。
- [x] AC2：创建好友房后服务端不启动牌局计时器或机器人动作，创建者进入四座等待房并占据一个座位。
- [x] AC3：加入好友房的真人立即占据空座位，所有房内玩家看到一致的四座占用和准备状态。
- [x] AC4：不足四名真人或任一真人未准备时均不能开局；四名真人全部准备后只启动一次新局。
- [x] AC5：新局开始时四名玩家均看到开局提示，随后正常进入既有牌桌流程。
- [x] AC6：每局结算后返回等待房、清空四人准备状态；再次四人全准备后开启下一局。
- [x] AC7：跨局保留房间码、座位、房主、底分和累计积分，重置单局状态。
- [x] AC8：房主主动解散立即关闭房间并回主页，不等待本局结束。
- [x] AC9：刷新、重连、重复准备请求和多人近同时准备不会导致座位重复、重复开局或状态倒退。
- [x] AC10：既有麻将规则与结算测试继续通过，并新增好友房等待、准备、局间回房和人机入口测试。
- [x] AC11：对局中仅当前行动玩家附近显示清晰箭头，行动玩家变化时箭头正确移动，等待或本局结束时隐藏。
- [x] AC12：等待房玩家可准备和取消准备；取消后不会误开局，四人重新同时准备才开局。
- [x] AC13：房主解散生效后所有房内客户端回主页并看到“房主已解散房间”。
- [x] AC14：主动离房释放座位且不能凭原页面直接恢复；房主离开时身份转给仍在房间的真人。
- [x] AC15：只有好友等待房的当前房主可以修改底分，修改后所有准备状态被清空。
- [x] AC16：好友对战玩家可实时收发房间短消息；非成员、等待阶段和非法消息被服务端拒绝。
- [x] AC17：聊天消息位于牌桌外且在 5 秒内渐隐移除，桌面及手机横屏均不遮挡麻将。
- [x] AC18：没有主要合法动作时，手牌上方不占位；合法动作变化时仅显示对应的六类主要按钮。
- [x] AC19：响应弃牌时只显示合法的碰和/或杠，辅助“过”仍可操作且不与主要按钮重复。
- [x] AC20：出牌、放赖、基础动作和自摸具有清晰层级；选择校验、44px 触控、双主题、桌面与手机横屏均通过验收。
- [x] AC21：普通牌二次点击只提交一次出牌；切换选牌、赖子选择、忙碌状态和非法阶段均不会误提交。
- [x] AC22：命令提交具备同步防重和超时恢复；断线重连重新订阅并显示网络状态，不产生重复监听器。
- [x] AC23：摸牌、最新弃牌和手牌重排具备自然动画；首次加载、断线恢复和减少动态效果模式直接展示最终状态。
- [x] AC24：轮到本人时本人信息、手牌区和倒计时形成一致焦点；提交中明确显示当前动作且立即锁定操作。
- [x] AC25：亮牌、赖子、放赖倍率与软硬胡结算有清晰且不过度的差异化反馈。
- [x] AC26：PC、平板和手机横屏无新增遮挡；阶段性及最终 lint、typecheck、测试和生产构建通过。
- [x] AC27：好友房等待满 3 分钟仍未开局时自动关闭；进入局间等待后重新计算 3 分钟，正常开局不会误关。
- [x] AC28：超时、房主解散和最后一名真人离房均关闭并回收内存；其他玩家看到与原因一致的提示。
- [x] AC29：房主离开且仍有真人时只转让房主、不关闭房间；新房主立即获得设置和解散权限。
- [x] AC30：iOS Safari 横屏安全区、动态地址栏和已安装 PWA 独立窗口布局可用；manifest、图标和 service worker 随生产构建发布。

## Out of Scope

- 公开匹配、账号登录、观战、历史记录和回放。
- 改变麻将牌型、倍率、倒计时、托管或机器人出牌策略。
- 大规模并发或多节点房间迁移。
