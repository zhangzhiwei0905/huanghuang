# 修复小程序体验版登录

## Goal

修复微信小程序体验版中“选择头像、填写昵称后点击进入晃晃没有可见反应”的问题，使首次登录在发布环境稳定完成。昵称使用微信官方昵称填写能力，由用户在微信键盘中选择当前微信昵称，选中后仍可手动修改。

## Background

- 用户确认同一构建在真机调试中可用，但上传为体验版后，头像能选择，填写名称后点击登录没有可见反应。
- 线上容器日志显示真机调试链路曾完整到达 `POST /api/upload/avatar` 和 `POST /api/auth/wechat`，两者均返回 HTTP 200；体验版失败操作没有产生新的头像上传请求，故失败发生在微信客户端到服务器之间。
- `project.config.json` 和本地私有配置都设置了 `urlCheck: false`，可让开发者工具/真机调试掩盖体验版会强制执行的合法域名限制。
- 当前头像上传使用 `Taro.uploadFile()`；微信后台的 `uploadFile` 合法域名与 `request` 合法域名是两个独立配置。选择头像只返回本地临时文件，所以“能看到头像”不代表上传成功。
- 当前错误文本由首页渲染在登录 `Form` 外侧；横屏根容器是横向 flex，错误可能出现在登录卡片右侧甚至视野外，导致失败看起来像“点击无反应”。
- 当前生产构建已指向 `https://huanghuang.amazingzz.xyz`，线上 `/health/live` 正常。
- 微信在 2022 年调整头像昵称获取规则后，不允许小程序通过 `openid`、`wx.login` 或旧用户资料接口静默换取真实微信号/昵称。支持的合规能力是 `Input type="nickname"`：用户点击输入框并在微信键盘选择微信昵称，然后可继续编辑。

## Requirements

### R1 体验版头像上传

- 首次登录不得把成功依赖于 `uploadFile` 独立合法域名配置。
- 客户端应先把 `chooseAvatar` 临时图片压缩到适合头像展示的尺寸，再读取为 base64，通过普通 `Taro.request` POST 到生产服务器。
- 服务端新增受大小限制的 JSON 头像上传接口，必须校验 base64、解码后大小及 PNG/JPEG 文件头，只保存合法图片。
- 新接口继续把头像写入现有 `AVATAR_DIR`，返回现有 `/avatars/<filename>` URL，不修改数据库和房间投影。
- 现有 multipart `/api/upload/avatar` 保留兼容，不破坏旧体验版或其他客户端。

### R2 昵称带入与修改

- 登录输入框继续使用 `type="nickname"`，以便微信键盘提供当前微信昵称。
- 页面必须明确说明“点击昵称框，在微信键盘中选择微信昵称”，避免用户误以为会静默自动填充。
- 微信昵称进入输入框后必须允许用户继续修改；登录提交读取原生 `Form` 的最终值。
- 不使用已失效或只能返回“微信用户”的旧头像昵称授权方式，不尝试读取微信号。

### R3 可见反馈与失败恢复

- 登录按钮点击后立即变为明确的忙碌文案。
- 头像处理、上传和微信登录阶段应显示卡片内进度。
- 校验错误、文件读取错误、请求错误和微信登录错误必须显示在登录卡片内部。
- 失败后必须解除 busy、保留本地头像和已输入昵称，允许直接重试。
- 服务端 HTTP 非 2xx 时客户端应展示可诊断错误，不得因为 JSON 解析或普通对象错误再次丢失信息。

### R4 服务与发布

- 客户端所有请求继续访问 `https://huanghuang.amazingzz.xyz`，不启动本地服务。
- 服务端改动通过现有阿里云 Docker 部署链路上线；无数据库迁移。
- 小程序生产构建必须显式注入线上 API 地址。
- 不代替用户上传新的微信体验版，但交付可直接上传的最新 `dist`。

### R5 单一登录入口与独立账户区

- 未登录首页不再同时展示头像选择、昵称输入和提交按钮，只展示一个明确的“微信登录”主按钮。
- 点击“微信登录”后进入轻量资料完善层；用户已确认采用“单一入口按钮 → 资料完善层 → 完成登录”的两段式交互。由于微信要求用户分别操作 `chooseAvatar` 和 `Input type="nickname"`，该层继续提供头像选择和昵称确认，但不长期占据首页。
- 资料完善成功后关闭登录层，首页同时展示当前头像和昵称。
- 已登录状态提供独立的“退出登录”按钮；按钮不再藏在创建/加入房间表单的“身份”字段中。
- 退出登录清除本地会话并立即回到单一“微信登录”入口，不修改服务器身份模型。

### R6 已有微信身份快速恢复与账户区轻量化

- 微信平台不提供首次登录时静默读取当前昵称的接口；原生 `Input type="nickname"` 仍作为首次资料填写入口，并允许手动修改。
- 点击“微信登录”时，客户端应先用 `wx.login` 尝试恢复服务器中已由同一 `openid` 保存的头像和昵称；已有身份直接完成登录，不再要求重复填写昵称。
- 若该 `openid` 从未完成过资料登录，服务器只返回“需要完善资料”，不得创建“微信玩家”占位身份；客户端再打开头像昵称资料层。
- 已登录账户区不显示包裹头像和昵称的白色长方形卡片；头像与昵称直接悬浮在背景上。
- “退出登录”保留至少 44px 点击区域，但可使用更小的内部视觉按钮，降低右上角占用。

## Acceptance Criteria

- [ ] 选择头像后仍立即显示本地预览。
- [ ] 点击昵称框时能使用微信昵称键盘；选择昵称后可继续修改。
- [ ] 点击“进入晃晃”后按钮和卡片内立即显示处理进度。
- [ ] 头像通过普通 `request` 域名上传，不依赖 `uploadFile` 合法域名。
- [ ] 合法 PNG/JPEG base64 上传返回 `/avatars/...`，无效 base64、错误文件头和超限图片被拒绝。
- [ ] 头像上传成功后，客户端用最终昵称和头像 URL 完成 `/api/auth/wechat` 登录。
- [ ] 任一失败路径在卡片内显示原因、解除 busy 并可重试。
- [ ] 旧 multipart 头像上传接口继续可用。
- [ ] 服务端和小程序类型检查、lint、格式检查及完整测试通过。
- [ ] 服务端生产部署后健康检查返回 200，新 JSON 头像接口在生产环境完成正向/反向探测。
- [ ] 生产小程序构建只包含 `https://huanghuang.amazingzz.xyz`，不包含本地 API 地址。
- [ ] 通过微信开发者工具 11352 验证登录卡片、昵称引导、按钮忙碌/错误反馈和成功链路页面切换。
- [x] 未登录首页只显示一个“微信登录”主入口，不直接铺开头像和昵称表单。
- [x] 点击登录入口后可完成头像选择、微信昵称选择及手动修改。
- [x] 登录成功后首页同时显示头像和昵称。
- [x] “退出登录”作为独立账户操作显示，创建/加入房间表单不再内嵌“重新登录”。
- [x] 退出后会话被清除，并返回单一登录入口。
- [x] 已完成过资料登录的同一微信用户再次点击登录时，自动恢复服务器保存的头像和昵称。
- [x] 首次微信身份快速恢复返回“需要完善资料”时，不创建或覆盖服务器身份。
- [x] 右上角头像昵称不再带白色长方形底框，退出按钮视觉尺寸明显缩小。

## Out of Scope

- 静默读取用户微信号、微信昵称或头像。
- 修改微信公众平台管理员配置。
- 数据库结构、用户身份模型或房间协议调整。
- 代替用户上传体验版或发布正式版。
