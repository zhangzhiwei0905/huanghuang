# 优化四席碰杠放赖布局

## Goal

调整微信小程序横屏牌桌中四个座位的公开牌组、本家身份卡和听牌辅助展示，让碰牌、各类杠和放赖始终靠近所属玩家，本家头像不被手牌遮挡，并让听牌信息对新手更易读。

## Background

- 当前实现已把玩家身份卡与公开牌组拆成独立的 `.player-station` 和 `.player-meld-rail`，数据只渲染一次，方向正确。
- 公开牌组轨道仍使用固定大宽度：上家与本家为至少 `300px`，左右家为固定两列至少 `146px`。
- 固定容器在满组场景中容量足够，但在“仅放赖”或只有少量碰杠时会留下大量空白，导致牌组看起来悬在牌桌中间或远离所属玩家。
- 上家轨道使用固定 `top: max(15.5vmin, 62px)`，与身份卡间距偏大，是当前最明显的问题。
- 已有极限布局截图只覆盖多组碰杠，没有覆盖四个座位分别“仅放赖”和少量副露的稀疏状态。

## Requirements

### R1 四席归属清晰

- 上家公开牌组在身份卡正下方紧凑居中，缩短身份卡与牌组之间的视觉间距。
- 左家公开牌组位于身份卡下方并向牌桌内侧展开，不越过左侧安全区。
- 右家公开牌组位于身份卡下方并向牌桌内侧展开，不贴出右侧安全区。
- 本家公开牌组位于手牌上方的保留带内，向左侧可用空间展开，不遮挡本家身份卡、手牌和操作区。

### R2 稀疏与满组状态一致

- 每个座位只有一组碰、杠或仅一张放赖时，轨道按内容收缩，不保留导致错位的大面积空白。
- 多组碰杠与放赖同时存在时，组间边界、牌型标签和数量仍清楚可见。
- 左右家三到四项公开信息使用两列布局；达到四组碰杠并带放赖的五项极限状态时使用三列两行，避免第三行侵入本家底部轨道；内容较少时不得因空列产生位置跳跃。
- 上家与本家在可用横向空间内一次性展示公开信息，不增加滚动。

### R3 保持现有行为

- 不修改服务端投影、座位映射、牌局规则、碰杠类型或放赖计数。
- 继续复用 `MahjongTile compact`、现有标签和视觉色系。
- 公开牌组保持 `pointer-events: none`，不得阻挡手牌选择和动作按钮。
- 仅做可审查的局部结构类名和 SCSS 调整，不重写页面。

### R4 本家身份区避让手牌

- 开局后，本家身份卡移到手牌上方的右侧安全带，不再和横向手牌共用底部一行。
- 身份卡不得遮挡本家公开牌组、中央操作按钮、右家公开牌组或牌河。
- 小屏横屏和手牌较多时，头像、昵称、积分、张数和倍率仍完整处于身份卡内。

### R5 公开牌组文字更克制

- 四个座位的碰、明杠、暗杠、加杠、放赖标签统一缩小。
- 放赖数量字号同步缩小，但仍保持足够的字重和对比度。
- 不缩小麻将牌面，不牺牲牌型辨识度。

### R6 听牌辅助改为纵向白色信息卡

- 听牌辅助使用白色或暖白色卡片，不再使用黑色底。
- 可胡牌种纵向展示；硬胡排在软胡上方，没有硬胡时只展示软胡。
- 每一项都清楚展示胡牌牌面、胡牌类型、合并后的倍率和真实公开剩余张数。
- 倍率和剩余张数使用更明显的字号、字重和色块层级。
- 数据继续来自服务端 `tingHints` 公开投影；客户端只负责排序和展示，不重新推算暗牌。

### R7 听牌卡保持紧凑且不挤压操作区

- 听牌卡使用内容自适应高度，不为一项听牌保留多行空白。
- 卡片作为操作行上方的浮层展示，不参与本家纵向排版，展开前后出牌按钮位置保持不变。
- 一项听牌显示一行；两项以上最多显示两行并在卡内纵向滚动。
- 倍率与余牌数紧邻排列，避免用两端对齐制造大块无意义空白。

### R8 创建房间可配置出牌时长

- 小程序创建好友房和人机对战时增加原生下拉选择，选项为 20 秒、25 秒、30 秒，默认 20 秒。
- 选择值通过共享创建房间协议传给服务端，并进入房间快照与投影。
- 真人 `TURN_DECISION` 使用房间配置生成 `actionDeadlineAt`；碰杠响应继续使用 5 秒，机器人继续使用快速决策时长。
- 未包含该字段的旧客户端请求和旧房间快照回退为 20 秒。
- 等待房和牌桌顶部信息区显示当前房间的出牌时长。

## Acceptance Criteria

- [x] iPhone 12/13 Pro 横屏尺寸下，上家的“仅放赖”紧贴身份卡下方，不再悬在牌桌中央。
- [x] 四个座位分别在“仅放赖”“一组碰/杠”“四组碰杠并带放赖”状态下，公开牌组都能明确归属于对应玩家。
- [x] 左右玩家的稀疏状态不因固定空列产生明显偏移，满组状态不遮挡中央信息区或牌河。
- [x] 本家公开牌组不遮挡手牌、听牌标识、听牌候选卡、操作按钮或右下身份卡。
- [x] 长昵称、离线状态和活动座位高亮仍保持在身份卡内正常显示。
- [x] 小程序类型检查、生产构建和格式检查通过。
- [x] 构建产物继续使用 `https://huanghuang.amazingzz.xyz`，不回退到本地 URL。
- [x] 使用包含碰、杠和放赖的视觉夹具完成四席截图验证。
- [x] 本家身份卡位于手牌上方右侧，在 14 张手牌和横向窄屏下不被手牌覆盖。
- [x] 四席碰杠放赖标签和放赖计数统一变小，麻将牌面尺寸保持不变。
- [x] 听牌卡为白底，可胡牌种纵向排列，硬胡始终在软胡上方。
- [x] 倍率与真实公开剩余张数在听牌卡中具有明确视觉强调。
- [x] 新增展示排序具备单元测试，并重新完成类型、测试、构建和视觉验证。
- [x] 听牌卡宽度和高度按内容收紧，三种候选时不再出现大块中间空白。
- [x] 展开听牌卡前后出牌按钮保持在同一位置，不再被卡片顶开。
- [x] 创建好友房和人机对战时可从 20、25、30 秒中选择出牌时长。
- [x] 服务端拒绝其他时长，并使用选择值生成真人回合截止时间。
- [x] 旧创建请求和旧快照默认使用 20 秒，房间投影可读取配置值。

## Out of Scope

- 不调整牌河、中央亮牌区、手牌排序、听牌规则或剩余张数算法。
- 不改变结算页布局。
- 不增加新的依赖、图片资源或动画系统。
