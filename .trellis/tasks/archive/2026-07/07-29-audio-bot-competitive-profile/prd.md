# 修复胡牌音效并补齐机器人竞技档案

## Goal

修复真机上硬胡/软胡音效偶发只播放半截的问题，并让排位赛预置机器人像真人
玩家一样展示其真实、持久化的段位和五类竞技成就。

## Background

- `yinghu.mp3` 与 `ruanhu.mp3` 本地源文件和裁剪文件均约 2.33 秒，播放器没有
  主动停止胡牌音效的计时器。
- `useGameAudio` 会在每个房间投影更新时调用 `GameAudioPlayer.warmup()`；当前
  warmup 在本地缓存尚未完成时会反复向同一最终路径下载全部音效。
- 缓存命中只通过 `accessSync` 判断“文件存在”，并不区分完整文件和下载中断
  留下的半成品，因此损坏文件会在后续牌局持续被播放。
- 预置排位机器人已通过 `ensureRankedBotSession` 拥有真实竞技档案，段位和五类
  成就会按真实结算持久化；它们不是展示用假数据。
- `RoomService.project` 构建公开档案查询列表时显式排除了
  `controller === "BOT"` 的座位，导致有真实 session id 的排位机器人仍投影为
  `competitiveProfile: null`。

## Requirements

- R1：每个 `GameAudioPlayer` 实例最多启动一次缓存预热，不因房间投影刷新重复
  下载同一批文件。
- R2：音频先下载到微信临时路径，成功后再移动到版本化的最终缓存路径；不得
  直接向可播放路径写入网络流。
- R3：启用新的缓存版本目录，使已经存在于手机上的旧损坏缓存不再被读取。
- R4：缓存未就绪或写入失败时继续使用云端临时 URL 播放，不阻塞当前音效。
- R5：普通好友房/人机房的无 session 机器人保持无竞技档案；有真实 session
  id 的预置排位机器人必须查询并投影真实公开竞技档案。
- R6：机器人公开档案使用与真人相同的 `PublicCompetitiveProfile`，包含具体
  段位文字和放赖、明杠、碰亮牌、补杠、暗杠五类成就，不新增机器人专用假字段。
- R7：机器人完成竞技动作和结算后，头像详情里展示的档案必须反映数据库中的
  最新成就与段位。
- R8：不改变竞技积分公式、段位算法、机器人策略或公共协议结构。

## Acceptance Criteria

- [ ] AC1：连续多次调用 `warmup()` 时，每个缺失音频只发起一次下载。
- [ ] AC2：下载完成前 `play()` 仍从云端 URL 播放；下载成功并原子保存后，
  后续播放才使用版本化本地路径。
- [ ] AC3：旧 `audio/` 缓存不会被新版本读取，胡牌音效不再因历史半截文件
  提前结束。
- [ ] AC4：排位房间投影中所有预置机器人均包含非空 `competitiveProfile`，
  前端现有头像详情弹窗无需特殊分支即可展示段位和五类成就。
- [ ] AC5：机器人完成一项竞技成就后，对应投影计数增加，真人计数不被误增。
- [ ] AC6：好友房普通机器人仍投影 `competitiveProfile: null`。
- [ ] AC7：服务端和小程序相关单测、全仓 lint/typecheck/test 与小程序生产
  构建全部通过。

## Out of Scope

- 不新增胜场、负场、胜率等当前协议中不存在的战绩字段。
- 不为预置机器人伪造头像图片；`avatarUrl: null` 继续使用现有机器人头像占位。
- 不修改或重新上传云存储中的胡牌音频源文件。
