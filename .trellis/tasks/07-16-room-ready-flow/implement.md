# 房间准备与人机入口流程优化：实施计划

## 1. 协议与房间状态模型

- [x] 在 `packages/protocol` 增加 `RoomMode`、`RoomStage`、大厅座位投影及创建模式校验。
- [x] 扩展 `RoomProjection`，明确等待房与牌桌阶段；为局 ID、开局时间和四座状态提供类型化字段。
- [x] 在 `RoomService` 中加入新快照归一化函数，迁移旧 JSON 房间并移除运行期双模型分支。
- [x] 将房间累计积分、下一庄家和可空 `round` 作为房间级状态，建立统一 `startRound`/`finishRound` 转换函数。

验证点：`pnpm typecheck`；旧快照构造测试；新好友房无牌局、无计时器、无机器人。

## 2. 服务端好友房生命周期

- [x] 创建 `FRIEND` 房时只占据首个固定座位并进入 `WAITING`。
- [x] 加入时占据空座，拒绝人机房与满员房，并保持房主转让/离房规则。
- [x] 重写准备逻辑：仅好友等待房可准备，重复请求幂等，四真人全准备只开一局。
- [x] 局终结算后复制累计积分和下一庄家；结算展示窗口结束后回到等待房并清空准备状态。
- [x] 等待阶段立即解散、进行中本局后解散继续符合既有约束。

验证点：新增创建、加入、满员、准备不足、并发式重复准备、四人开局、局终回房、跨局积分和解散单元测试。

## 3. 服务端人机生命周期

- [x] 创建 `BOT` 房时复用现有一真人三机器人开局逻辑。
- [x] 禁止加入和邀请人机房。
- [x] 人机局终停止自动续局；实现仅房内真人可调用的继续接口，保留累计积分和下一庄家。
- [x] 双击继续、错误阶段继续和退出人机房具备确定性行为。

验证点：机器人轮转旧测试迁移到 `BOT` 模式；新增结果停留、继续、积分保留、拒绝加入与退出关闭测试。

## 4. 前端入口、等待房和结算控制

- [x] 更新 `HomeScreen`，增加同级人机入口，好友创建不再显示“创建并开局”。
- [x] 更新 API 与 `useRoom`，发送房间模式、处理房满/不可加入错误并提供人机继续动作。
- [x] 按 `RoomStage` 重构 `GameTable` 分支，使用 `lobbySeats` 固定展示四座占用、在线和准备状态。
- [x] 好友结算展示后由服务端投影回到等待房；人机结算增加“继续游戏/退出到主页”按钮。
- [x] 好友房保留邀请按钮，人机牌桌隐藏邀请入口。

验证点：组件/投影逻辑测试，手工检查创建好友房、加入、准备、人机继续和退出流程。

## 重点回滚点

- 协议/服务端状态模型必须与前端同一批发布，不能只部署单侧。
- 旧快照归一化测试未通过时不部署；若生产快照异常，回滚应用同时恢复部署前数据库备份。
- 本任务不改游戏引擎规则；如规则测试出现变化，优先回滚房间层改动并定位越界访问。
