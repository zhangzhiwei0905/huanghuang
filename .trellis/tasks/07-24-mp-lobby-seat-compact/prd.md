# 收敛小程序候场座位视觉

## Goal

降低好友房候场页面的视觉拥挤感，让四个玩家信息回归牌桌的辅助层级。候场玩家信息的头像、字号、间距和信息框尺寸与真实对战页面的玩家信息保持一致，同时保留准备状态和自己方位的准备操作。

## Background

- 当前 `.lobby-seat` 使用至少 154px 宽、66px 高的高不透明米白卡片；自己的卡片还会扩大到至少 245px × 76px，因此四个座位和中央等待区互相争夺视觉空间。
- 候场头像使用 40–50px，而真实对战 `.seat-avatar--player` 使用 26–34px。
- 候场昵称和积分字号也高于真实对战 `.player-station`。
- 当前非自己玩家的准备状态占用独立一行，进一步放大了卡片高度。
- 所有头像、昵称、积分、联网和准备数据已经存在，本次不需要修改接口或服务端。

## Requirements

### R1 尺寸与实战玩家信息一致

- 候场头像使用与真实对战玩家头像相同的尺寸范围。
- 候场昵称、积分和状态使用与 `.player-station` 相同的字号及紧凑间距。
- 非自己玩家的信息框使用与真实对战玩家信息相同的宽度、内边距和圆角基线。

### R2 弱化玩家信息框

- 降低候场信息框的背景不透明度、边框和阴影强度，避免四个大卡片成为页面主视觉。
- 准备、离线和空位仍需可辨认，但通过轻量文字、色彩或细边框表达，不通过整块高饱和背景强调。
- 房主和“我”标识继续显示，但缩小到不打断昵称阅读的辅助层级。

### R3 收敛状态与准备操作

- 将积分与准备/离线状态收敛到同一条元信息中，取消非自己玩家单独占用的状态行。
- 自己的玩家信息区域保持与其他玩家一致；准备/取消准备按钮作为相邻独立操作，不把自己的信息框整体放大。
- 准备按钮继续保留 44px 左右的可靠触控区域、忙碌态和按压反馈。

### R4 保持现有行为与单屏布局

- 不改变准备、取消准备、底分、分享、离开、解散和自动开局逻辑。
- 不改变开局 3、2、1 覆盖层及实战牌桌布局。
- 页面继续保持横屏单页、无滚动条，并避让左侧刘海安全区。
- 使用正式服务器构建，通过微信开发者工具 11352 复测候场未准备和已准备状态。

## Acceptance Criteria

- [x] 候场四个头像的可视尺寸与真实对战玩家头像一致。
- [x] 非自己玩家信息框的尺寸、字号和间距与真实对战 `.player-station` 基线一致。
- [x] 玩家信息框的背景、边框和阴影明显弱于当前版本，牌桌中央留白增加。
- [x] 昵称、积分、准备/未准备/离线状态及房主/自己标识仍完整可见。
- [x] 自己的信息框不因准备按钮而放大；准备按钮在信息框旁独立显示。
- [x] 准备与取消准备功能、忙碌态和服务器同步保持正常。
- [x] 页面没有新增遮挡、刘海侵入或滚动条。
- [x] lint、typecheck、测试、格式检查和正式服务器生产构建通过。

## Out of Scope

- 修改中央等待区、顶部工具栏或背景素材。
- 修改实战牌桌玩家信息样式。
- 修改房间协议、准备规则或服务端自动开局条件。
- 上传体验版或正式发布小程序。
