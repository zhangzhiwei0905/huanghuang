# 优化小程序牌桌布局并修复听牌提示 — 技术设计

## 1. Scan

### 1.1 当前结构

`apps/miniprogram/src/pages/room/index.tsx` 在同一个 `.player-station` 中依次渲染：

1. 头像、昵称和一整行元信息；
2. 该座位的全部碰杠牌组；
3. 最近一张放赖与累计数量。

四个 `.player-station` 都绝对定位。左右座位为了容纳副露已被放宽到 `46vmin`，本玩家卡片位于左下区域。当左侧和本玩家都有多组副露时，两个动态扩张的盒子进入同一空间。

### 1.2 已确认的故障

- `.player-station__meta` 使用 `white-space: nowrap`，没有 `overflow: hidden` 或可换行结构，导致上、下座位元信息越界。
- 副露内容决定身份卡的宽高，位置规则无法为最坏的四组杠同时预留空间。
- 听牌客户端和协议代码已经存在，但线上服务镜像早于 `a6f31d0`，不会生成 `tingHints`。

## 2. Diagnose

### 2.1 信息层级

玩家身份和副露承担不同任务：

- 身份卡：快速识别玩家、积分、手牌数、个人倍率、在线状态；
- 副露轨道：持续展示公共牌局信息，最多四组碰/杠和放赖。

把两者放进同一张卡会让身份识别组件承担不受控的牌面容量，既造成边界溢出，也破坏四席空间分工。

### 2.2 布局约束

- 横屏手机高度通常只有 390–430 CSS px，牌面尺寸的 `px` 下限比 `vmin` 更早生效。
- 最坏一组杠包含四张牌；四组最多 16 张公开牌。
- 左右席可用纵向空间更适合 2×2 组网格；上下席可用横向空间更适合单行四组。
- 本玩家手牌、动作条、听牌卡片已经占用底部区域，副露必须落在其上方的固定轨道中。

## 3. Fix

### 3.1 组件结构

为每个玩家渲染两个同级元素：

```text
PlayerStationIdentity
  avatar
  nickname
  stat chips

PlayerMeldRail
  meld group × 0..4
  released wildcard group
```

首轮可保留在房间页内渲染，不引入新状态或改变投影。两个元素共享座位位置类和活动座位状态类，但拥有独立的几何规则。

### 3.2 身份卡

- 固定合理宽度，所有子元素使用 `min-width: 0` 和 `box-sizing: border-box`。
- 昵称单行省略。
- 把原来一整行元信息拆成短状态项：`积分 N`、`N张`、`×N`、`离线`。
- 状态项允许在卡片内换行，数值使用等宽数字；关键状态不以省略号丢失。
- 活动座位边框和脉冲仍只作用于身份卡，避免整条副露轨道发光。

### 3.3 四席副露轨道

- `.player-meld-rail.pos-opposite`：身份卡下方居中，最多四组横向一次展示。
- `.player-meld-rail.pos-self`：左侧轨道下方、操作按钮左侧的独立横向带，最多四组横向一次展示；较窄的身份卡留在右下角，手牌保持居中。
- `.player-meld-rail.pos-left`、`.pos-right`：各自边缘内侧使用两列两行网格，控制最大宽高。
- 每组使用独立的轻量底板或分隔，保留牌组边界；牌型标签从现有 `MeldKind` 映射为碰、杠、暗杠、补杠等短标签。
- 牌面继续复用 `MahjongTile compact`，并使用真实手机高度下验证过的 px 下限进行容量计算。
- 放赖保持独立小组，必要时作为网格中的一个项目，不与身份卡混排。
- 轨道无滚动；四组公开信息一次性可见。

### 3.4 层级和避让

```text
顶部：对家身份卡 → 对家副露轨道

左侧：左家身份卡
      左家 2×2 副露轨道    中央牌河/亮牌区    右家 2×2 副露轨道
                                                     右家身份卡

底部：本家副露轨道              听牌卡 / 动作条
                                      手牌      本家身份卡
```

- 身份和副露使用同一公共信息层级，低于底部交互层，高于牌桌背景。
- 副露轨道禁用点击事件，不阻挡出牌。
- 左右副露轨道设置固定宽度 floor，不能因牌组数量继续向中央扩张。
- 本家副露轨道的 bottom 由手牌和动作区最大高度推导，避免与听牌卡共占一层。

### 3.5 听牌提示

客户端继续使用服务端投影：

```text
RoomProjection.tingHints
  → indexTingHints(discardTileId)
  → 手牌“听”标识
  → selectedTileId
  → TingHintCard(waits)
```

本次不复制规则，只补充以下防回归：

- 收到不含当前选择牌的投影时，候选卡自动消失；
- 选中的物理牌已从手牌移除时清除本地选择；
- 用现有单测覆盖索引与切换，用服务测试覆盖真实投影。

线上修复的关键是部署包含 `a6f31d0` 的服务端镜像。镜像使用当前提交 SHA 作为 `APP_REVISION`，上线后读取容器 label 并请求房间投影核验。

## 4. 不变项

- 不改胡牌规则、倍率公式、公开剩余数量算法和赖子规则。
- 不读取牌墙或其他玩家暗手。
- 不改座位映射、牌河结构、出牌二次点击交互和动作合法性来源。
- 不改微信登录、头像上传和生产域名。
- 不迁移或重建 SQLite 数据。

## 5. 风险与控制

| 风险 | 控制 |
|---|---|
| 副露轨道遮挡牌河 | 四席使用专属几何区，按 844×390 最小视口做截图验证 |
| 四组杠仍超宽 | 按 tile px floor 计算轨道宽度；左右使用 2×2 组网格 |
| 元信息为了不溢出而不可读 | 拆为短状态项并在卡内换行，不截断关键数值 |
| 前端有提示但线上仍为空 | 同步部署服务端，以容器 revision 和真实投影双重验收 |
| 部署覆盖微信配置或数据 | 复用生产 `.env` 与 `game_data` volume，不执行数据库删除/重建 |
