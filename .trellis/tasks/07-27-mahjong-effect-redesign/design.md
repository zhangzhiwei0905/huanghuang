# 设计：裁剪点与时长对齐

## 关键洞察

`runtime.ts` 里 `stretchLottieTiming(animationData, durationMs)` 会把
`op - ip` 帧数拉伸／压缩到 `durationMs`：`fr = frameCount / (durationMs/1000)`。
这意味着"每个动作在设备上播多快"由两件事共同决定：

1. `presentationProfiles[key].outPoint`——从完整源素材里截到第几帧（丢弃
   之后的内容，包括原设计里的"停留 + 淡出"尾巴）。
2. `EFFECT_VISUAL_DURATION_MS[action]`——截下来的这段内容要塞进多少毫秒里播完。

新素材是按 60fps 的设计节奏画的（`fr:60`），所以有一个很方便的换算：
`outPoint（帧） ≈ 目标可见时长（ms） × 0.06`。只要在这个附近的帧上找到一个
"主体已经清晰可读、还没进入长时间停留"的截点，就能让新素材在目标时长下
**几乎以原始设计速度播放**（不需要额外加速/减速，动作既不被压扁成一团模糊，
也不会被无意义地拖慢）。

另外，`MahjongEffectOverlay.scss` 已经给整个覆盖层加了 90ms 的
`transition: opacity` —— 也就是说 Lottie 播放到 `outPoint` 直接硬切，视觉上
仍然会有一个短促的淡出，**不需要在动画数据里自己画一段淡出尾巴**。这也是新
素材可以比旧素材裁得更狠的原因：旧素材的尾巴本来就是"停留 + 手工淡出"，
现在这两件事都可以交给裁剪点 + CSS 过渡来做。

## 逐个动作的裁剪依据

以下时间轴引用自新素材（详见任务对应会话产出的设计稿），`t` 为帧号，60fps。

### 碰 → outPoint 27（450ms，1.00×）

- t0–16：两道弧线对撞、冲击环炸开、碰字章开始出现。
- t9–12：碰字章 snap 完成，进入 100% 不透明度并保持到 t36。
- t27：弧线、冲击环早已消失（分别在 t16、t26 前完成淡出），碰字章清晰可读，
  粉屑仍在自然飘落——是一个干净的截断点，不会腰斩任何"正在进行中"的主体
  动作。
- 丢弃 t28–45：碰字章的长停留（到 t36）和淡出（t36–45），这段对"碰"这种
  高频、低权重动作没有意义，且拖长可见时长。

### 杠 → outPoint 42（700ms，1.00×）

- t0–12：四张牌从四角砸入完成（最晚落地的牌 t9+12=21 完成着陆弹跳）。
- t13–24：白闪、暖芯、双冲击环、放射光陆续起爆，杠字章在 t20 开始出现。
- t42：杠字章已经完成"冲高回落"的定型动作（overshoot 在 t27 到顶，t37 微调
  完成，t42 时已稳定在接近 100% 的最终态），双冲击环、白闪都已经收尾，金币
  仍在上浮——同样是一个动作已"读完"但粒子仍有余韵的截断点。
- 丢弃 t43–75：杠字章的长停留（到 t58）和上飘淡出（t58–75），以及金币收尾。
  这部分是"重击后的从容感"，在 0.7s 预算里让不出空间。

### 补杠 → outPoint 39（650ms，1.00×）

- t0–16：三张原有的碰牌落位，光柱打开。
- t16–27：第四张牌落入最后一格，锁定环在落点炸开。
- t37：补杠字章的缩放曲线已经在 t37 到达 `[100,100,100]` 并开始保持
  （`[44,[100,100,100]]` 只是延续同一个值，不是新的动作）。
- t39：字章清晰可读、四张牌已经排成一排、锁定环炸开的观感已经传达完毕，是
  这个动作里最早能"读完"的一帧。
- 丢弃 t40–60：补杠比杠更弱的语义已经通过更少的环、没有放射光、更小的
  过冲比例体现，不需要额外的停留时间来强调。

### 放赖 → outPoint 48（800ms，1.00×）

- t0–14：预击闪电落下，画面第一次弱闪（预击闪电在 t14 完成淡出）。
- t18–44：主闪电劈中赖子牌，画面第二次强闪，放赖字章完成"冲高回落"定型
  （t34 到达 `[100,100,100]` 并开始保持）。
- t48：两次闪光都已经发生——"预击 + 主击"这个用来传达"加倍"的核心叙事
  已经完整播放，字章清晰可读。
- 丢弃 t50–84：字章的"二次脉冲"（t50–66，本来是为 2.1 秒版本设计的"加倍
  回声"）在 800ms 预算下没有空间；双闪本身已经承担了"加倍"的读法，这个
  取舍在 PRD 里已经标注为已知的简化，不是遗漏。

### 胡牌 → outPoint 63（1050ms，1.00×）

- t0–30：五张牌扇面飞入、两个灯笼落下摆动、金冠开始上升。
- t30–54：胡字章"落章"——超尺寸 + 倾角砸下（t38 触底），随后在 t46–48
  完成扶正回弹，白闪与方形震波同步完成（分别在 t45、t54 前结束）。
- t63：落章动作完整读完（冲击力 + 回弹），灯笼基本摆定（第二个灯笼的摆动
  在 t67 才完全收敛，t63 时已接近静止，可接受的轻微裁切），22 片金箔里已有
  20 片开始飘落（仅 2 片要到 t64/74 才启动，裁掉不影响整体"金箔雨"的观感）。
- 丢弃 t64–126：字章的"喜庆呼吸"（两次慢速脉冲，t66–108）是为完整 2.1 秒
  演出设计的收尾余韵，在 1.05s 预算下让位；红场从 t110 开始的进一步外扩
  同理省略。

## `layerNames` 白名单的处理

旧素材（尤其是 `peng.cjs`）在同一份源文件里塞了"完整版"和"精简版"两套
内容，`layerNames` 白名单的作用是从完整版里挑出精简版要显示的图层（例如
旧 `peng` 会把三张贴脸的牌图层过滤掉，只留章 + 冲击波 + 部分彩屑）。

新素材是直接按"最终呈现"设计的——没有为了以后可能要做精简版而预先塞入
多余内容，所有图层都是要显示的。因此 `presentationProfiles` 里
`layerNames` 这个过滤步骤对新素材是多余的：`applyPresentation` 改为只做
`ip`/`op` 裁剪和 `meta.presentation` 标注，不再按图层名字过滤。

如果以后需要在同一份源文件里再派生出"精简/完整"两个变体，可以再把过滤
逻辑加回来——但当前 5 个动作没有这个需求，加回一个不会被用到的过滤表反而
是无意义的维护负担。

## 风险与验证

- 用 `lottie-web` 的 canvas 渲染器（和小程序端 `lottie-miniprogram` 同一套
  能力子集）在本地过一遍每个动作在 `outPoint` 帧的静态画面，确认没有"动作
  飞到一半戛然而止"的观感（例如某张牌还在半空、某道粒子还没成型）。上面
  的逐个分析已经是按这个标准选的截点，但仍需要肉眼过一遍确认。
- `stretchLottieTiming` 对 `fr` 没有上限校验；如果后续调整
  `EFFECT_VISUAL_DURATION_MS` 导致目标时长明显小于 `outPoint/60`，播放会明显
  加速变糊——本次选择让所有五个动作都落在 1.00× 左右，暂不需要担心这个。

## 追加设计：消除尾部空锁与音频重叠

### 动画结束即推进

当前 `EFFECT_VISUAL_DURATION_MS` 比 `EFFECT_DURATION_MS` 短：杠系和放赖在
画面结束后仍分别空锁约 400ms、450ms；`RoomService.tick()` 又以 250ms 间隔
扫描，实际尾差还会增加 0–250ms。这正是“动作完成后还要等一会才落牌/摸牌”
的来源。

服务端 duration 改为与客户端目标可见时长完全一致，保留
`pendingEffectTransition` 的服务端权威提交机制，不改成客户端完成命令。
进程 tick 间隔从 250ms 缩短为 50ms，把到点后的最坏附加延迟限制在 50ms。

### 音频固定双槽（修正 latest-wins）

实机反馈证明 latest-wins 的听感错误：它虽然不重叠，却会把正在念的牌名截断，
且每条提示都 create/destroy `InnerAudioContext`，长局中原生资源抖动反而加重。

Git 历史 `fab59a1` 曾实现“URL 预热 + 两个 context 复用”，这更接近用户记忆中
的丝滑版本。本次恢复该方向并补上历史实现未处理好的两个边界：

1. context 总数严格固定为 2；两个槽都忙时直接丢弃新提示，不创建第三个，也
   不把它排进历史队列。
2. timeout 截取结束同样把 context 归还池中，而不是销毁；复用前调用
   `offEnded()` / `offError()` 清掉上一轮监听器，避免回调累积。

普通出牌间隔大于约 0.4–0.7s 时，每条牌名都会完整结束；只有确实快到双槽都
占用时才丢弃过量提示，听感不会落后于牌局。

### 点击到落牌的端到端延迟

此前只压缩了 `endsAt`，但点击命令仍走
`Socket command → ACK → HTTP refresh → projection → render`，同时
`room:update` 还会再触发一次 GET。改成 ACK 附带发起玩家的个性化
`RoomProjection`：发起端立即 `replaceProjection()`，服务器向其他 socket
定向发送各自的私有投影。特效到期的 tick 同样定向推送完成投影，去掉
“动画结束 → 版本通知 → HTTP GET → 才摸字”的尾延迟。老服务端没有
projection 时客户端保留 GET fallback。

另外，非胡牌动画当前先异步查询 player station 的 `boundingClientRect()`。
恢复历史 `d0c4d50` 已验证过的同步 station anchor 计算，但不恢复其中的特效
队列和 DPR canvas，避免引入无关复杂度。
