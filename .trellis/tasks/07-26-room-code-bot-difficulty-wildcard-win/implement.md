## 风险与回滚点

- 房间状态与投影改动完成后先跑服务端/协议全量测试，再开始两端 UI，避免在不稳定契约上并行堆叠界面。
- 观战成员测试必须验证四家 `hand` 均为 `null`；发现暗牌泄露立即停止 UI 集成。
- 双对子用例若在现有引擎层已通过，不重写 `evaluateWin`，只补齐失败的上层路径和回归覆盖。
- 上线前备份生产 SQLite 与旧镜像；新快照写入观战队列后，应用回滚必须同步恢复数据库备份。
